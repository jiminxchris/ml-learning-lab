## 시작 전에 학생에게 안내할 것

회원가입 없이 접속합니다. 슬라이더를 움직이면 브라우저가 다시 계산합니다. Python 탭의 코드는 학생 PC의 Jupyter·VS Code·Colab에 복사해 실행합니다. Python 출력 기록과 브라우저 실험의 자료는 다를 수 있습니다. 퀴즈를 세 문제 모두 맞히면 완료로 표시됩니다. 노트·진도는 현재 브라우저에만 저장되므로 학습 기록 내보내기를 권장합니다.

실제 Iris 150개를 쓰는 PCA 실험과 합성 자료를 쓰는 실험을 구분합니다. 합성 데이터는 원리를 분명히 보이기 위한 것이며 실제 업무 성능의 증거가 아닙니다.

## 1. 공통 기초

### 무엇을 예측하고 싶은가요? · question

광고 판매량·꽃 품종·비슷한 선수라는 세 질문을 제시하고 “정답이 있는가, 있다면 연속 수량인가 범주인가”부터 물어봅니다. 0/1이 숫자라고 회귀가 되는 것은 아닙니다. 군집 번호는 정답 품종 번호가 아니라 그룹 이름입니다.

학생 활동: 문제 카드를 바꾸고 입력·정답·평가 지표를 한 문장씩 설명합니다. 확인 문장: “매출의 원인을 증명하는 것과 매출을 예측하는 것은 다른 문제다.”

### 시험지를 미리 보면 안 되는 이유 · split

100칸에서 테스트 비율을 바꿔 자료 수를 확인합니다. 무작위 분할과 시간순 분할의 차이를 보고 아파트 미래 거래를 어느 방법으로 평가할지 토의합니다. 학습에서 규칙을 배우고, 검증에서 설정을 고르고, 테스트에서 마지막으로 확인합니다.

누출 사례: 자전거 casual+registered=count, 거래금액에서 계산한 ㎡당 가격, 예약 취소 뒤에만 알게 되는 상태. “예측하는 순간 이 값을 실제로 알 수 있는가?”를 반복 질문합니다.

### 스케일링은 정보를 지울까요? · scale

두 번째 특성의 단위 배수를 1→100으로 바꾸고 최근접 표본 번호를 확인합니다. 표준화를 켜고 같은 실험을 반복합니다. 입력의 상대적 크기·순서는 남아 있지만 거리 계산에서 특성별 기여 비율이 바뀝니다.

단위가 다르다고 모든 알고리즘에 표준화가 무조건 필요한 것은 아닙니다. 거리·패널티·수치 최적화가 척도의 영향을 받는지를 봅니다. OLS는 일반적인 전랭크 조건의 절편 있는 모델에서 가역적 선형 스케일 변화에 예측이 불변이며, 규제·유한 정밀도·최적화 문제는 별도입니다. 트리는 보통 표준화를 요구하지 않습니다.

### 교차검증은 여러 번 학습할까요? · validation

fold 수와 k 후보 개수를 바꾸고 학습 횟수를 계산하게 합니다. 3개 후보×5fold=15번 검증 학습, 최종 refit까지 16번입니다. 한 번의 cross_validate로 여러 지표를 계산할 수 있지만 후보별 검증 fold 학습 자체를 생략하는 것은 아닙니다.

테스트 정답으로 최적 k를 고르지 않습니다. Python은 Pipeline 안에서 스케일러를 fold별 fit합니다. 별도의 cross_val_score를 accuracy와 F1에 각각 호출하면 학습이 중복될 수 있습니다.

## 2. 회귀

### 점들 사이에 가장 좋은 선 긋기 · linear

기울기와 절편을 일부러 틀리게 놓고 잔차 선이 어떻게 길어지는지 봅니다. 최소제곱 버튼으로 학습 MSE를 줄입니다. 이상치 하나를 더했을 때 직선과 테스트 점수의 변화를 확인합니다.

질문: 점과 예측선의 세로 차이는 무엇인가? R²가 음수면 계산 오류인가? `predict([100])`와 `predict([[100]])`의 차이는 무엇인가? 새 입력이 학습 범위를 크게 벗어날 때 값이 나왔다는 이유만으로 믿어도 되는가?

### 입력이 여러 개면 무엇이 달라질까요? · multiple

TV·Radio·Newspaper 슬라이더 중 하나만 바꿉니다. 예측은 각 항과 절편의 합입니다. 표준화 계수의 단위와 원 단위 계수의 단위를 구분합니다. 중요도는 계수 크기 하나로 정해지지 않으며, 예측 변화가 인과 효과는 아닙니다.

브라우저 계수는 설명용 고정값입니다. Python은 작은 표에서 범주형을 OneHotEncoder로 바꾸고 수치형과 함께 학습하는 문법 예제입니다. 이를 실제 광고 데이터의 결과로 소개하지 않습니다.

### 곡선이 복잡할수록 더 좋을까요? · polynomial

차수를 1→3→9로 바꾸며 곡선과 오차를 관찰합니다. PolynomialFeatures는 x²·x³·교차항 같은 새로운 입력 열을 만들고 선형 모델이 그 계수를 배웁니다. 계수에는 선형이지만 원래 x에 대해 곡선이 될 수 있습니다.

다중 입력에서 차수가 9이면 각 특성을 9제곱한 열만 생기는 것이 아니라 총차수 9 이하의 조합이 생깁니다. 특성 수가 p일 때 bias 포함 열 수는 조합 C(p+d,d)이며 `include_bias=False`면 1을 뺍니다. 예를 들어 p=3,d=9는 219열입니다. 고차 다항은 수치적으로 민감하므로 다항 확장 후 스케일링과 규제를 검토합니다.

### 리지와 라쏘로 복잡함에 제동 걸기 · regularization

차수 9를 유지하고 alpha를 바꿉니다. Ridge는 계수를 작게 만들고 Lasso는 일부를 0으로 만들 수 있습니다. 너무 큰 alpha는 과소적합을 만들 수 있습니다. 무조건 규제를 더 강하게 한다고 테스트 성능이 좋아지지 않습니다.

alpha는 “TV를 두 배 중요하게”라는 중요도 비율이 아닙니다. 특성별 규제를 다르게 주는 것은 패널티 설계이며 영향력 두 배를 보장하지 않습니다. 브라우저는 MSE 기준 패널티, sklearn Ridge는 제곱오차 합 기준이므로 alpha 숫자를 그대로 비교하지 않습니다.

### 자전거와 아파트, 실제 문제로 연결하기 · projects

log1p 전후 막대와 expm1 복원을 확인합니다. 로그 변환은 필수가 아니라 큰 값의 차이와 오차의 강조 방식을 바꾸는 선택입니다. 초보 수업은 원 단위 모델부터 시작해도 됩니다.

자전거 datetime은 pd.to_datetime 후 dt.month·day·dayofweek·hour로 뽑습니다. 범주형은 학습에서 인코더를 fit하고 테스트에 transform합니다. 더미즈를 각각 쓴다면 학습 열 기준 reindex로 열 종류·순서를 맞추되, 학습에 없는 범주는 별도 해석이 필요합니다. 테스트에만 있는 범주를 학습했다고 주장하지 않습니다.

## 3. 분류

### 결정 트리는 질문을 나눕니다 · tree

깊이 1→7, Gini↔entropy를 바꾸고 공간이 나뉘는 모양과 학습·테스트 점수를 봅니다. 순수한 노드는 정답 종류가 하나뿐입니다. criterion은 더 잘 섞임을 줄이는 분할을 평가하는 방식입니다.

붓꽃의 꽃잎 길이·너비가 이 트리에서 높은 중요도를 가질 수 있지만, 히트맵의 숫자 label과 Pearson 상관만으로 모델 영향력·인과 효과를 확정하지 않습니다. 순서 없는 label의 숫자 재배치는 상관계수에 영향을 줍니다. 실제 품종별 분포와 검증 성능을 함께 봅니다.

### 가까운 이웃에게 물어보기 · knn

그림에서 새 점을 옮기고 k=1·5·15를 비교합니다. 이웃과 새 점을 연결한 선은 투표 대상입니다. 테스트 점이 학습 이웃으로 들어가지 않음을 강조합니다. k가 커지면 국소 구조가 평균화되지만 항상 좋은 것은 아닙니다.

### 확률을 결정으로 바꾸는 순간 · logistic

같은 모델에서 임계값만 0.2→0.8로 바꿉니다. 양성 예측 수, precision·recall이 어떻게 달라지는지 살펴봅니다. 계수를 새로 학습한 것이 아니라 확률을 범주로 바꾸는 기준을 바꿨습니다. 확률 추정의 보정 문제와 임계값 선택도 구분합니다.

### 정확도 95%, 정말 좋은 모델일까요? · metrics

95% 정확도 함정 버튼을 누릅니다. 실제 양성 5개를 하나도 찾지 못해도 음성이 많으면 정확도가 95%입니다. 혼동행렬은 행=실제, 열=예측입니다. TP·FP·FN·TN을 학생이 직접 설명하게 합니다.

support는 해당 클래스의 실제 표본 수입니다. precision은 예측 기준, recall은 실제 기준입니다. macro는 클래스별 지표의 같은 가중 평균, weighted는 support 가중 평균입니다. weighted F1이 높다고 소수 클래스도 잘 맞힌다는 보장은 없습니다.

### 모델을 비교하기 전에 공정한 절차부터 · pipeline

배깅 트리 수와 깊이를 바꿉니다. 브라우저는 복원추출 배깅의 원리이며 전체 RandomForest 구현은 아닙니다. Python은 실제 RandomForest와 GridSearchCV를 사용합니다.

로켓 실습에서 점수 1.0이 나왔던 상황을 연결합니다. 데이터가 쉬울 수도 있지만 결측 패턴·정답 유래 특성·중복·잘못된 분할을 점검합니다. 결측을 미리 전체 중앙값으로 채우는 대신 fold 안에서 SimpleImputer를 fit합니다. 범주형 Unknown·수치형 중앙값은 합리적 시작점이지만 데이터 생성 과정과 목표에 맞춰 검토합니다.

## 4. 군집

### 중심을 옮기며 비슷한 점 묶기 · kmeans

초기 중심 → 가장 가까운 중심에 할당 → 군집 평균으로 이동을 한 단계씩 반복합니다. 색은 그룹 이름이고 X는 중심입니다. n_init은 다른 초기화로 몇 번 실행할지 정하는 값이지 k도 갱신 횟수도 아닙니다.

단위와 상대적 가중치를 보고 표준화 여부를 정합니다. KMeans가 거리를 사용하므로 표준화는 흔한 시작점이지만 무조건 정답은 아닙니다. 원 단위·표준화 결과는 다른 거리 기준의 분석입니다.

### 군집은 몇 개가 적절할까요? · kchoice

같은 입력에서 k별 관성·실루엣을 비교합니다. 관성은 중심까지 제곱거리 합이며 k가 늘면 일반적으로 감소합니다. 엘보우는 감소 폭이 크게 줄어드는 지점이지 자동 정답은 아닙니다. 실루엣이 높은 k가 업무 질문에도 유용한지 봅니다.

붓꽃에서 k=2가 더 높은 실루엣을 가질 수 있습니다. 잘 떨어진 setosa와 나머지를 크게 나눈 구조가 거리 기준에 유리하기 때문이며 품종 세 종류를 부정하는 것이 아닙니다.

### 작은 묶음이 큰 가지가 되기까지 · hierarchy

덴드로그램의 잎은 표본, 합쳐지는 높이는 Ward 병합 기준을 나타냅니다. 가로 순서는 순위나 거리축이 아닙니다. 절단 k를 바꿔 같은 병합 이력에서 그룹 구성이 어떻게 바뀌는지 봅니다.

AgglomerativeClustering은 아래에서 위로 합치는 계층적 군집의 한 종류입니다. Ward·complete·average·single은 연결 기준입니다. Ward는 유클리드 기반 군집 내 제곱합 증가를 최소화합니다. 계층적 군집도 실루엣을 사용할 수 있지만 KMeans의 inertia_ 속성이 그대로 있는 것은 아닙니다.

### 빽빽한 이웃을 따라 연결하기 · dbscan

반달·고리 자료에서 eps·min_samples를 바꿉니다. 핵심점은 자기 자신을 포함한 이웃 수 조건을 만족합니다. 경계점은 핵심점 이웃이지만 자기 이웃 수는 부족할 수 있고, 잡음은 -1입니다.

eps는 군집 전체를 덮는 한 원의 반지름이 아닙니다. 핵심점의 연결을 따라 길게 이어질 수 있습니다. 결과가 2개라는 것은 현재 전처리와 설정에서 두 밀도 그룹이 나왔다는 뜻입니다. “최적 군집 수가 2로 입증됐다”가 아닙니다. 잡음을 제외하고 실루엣을 계산할 때 제외 비율도 함께 봅니다.

### 네 가지 측정값을 한 장에 담기 · pca

실제 Iris 150개를 4차원에서 군집화하고 동일 입력으로 PCA 투영합니다. 점의 위치는 PCA, 색은 군집 또는 실제 품종입니다. 색 기준을 바꾸어도 좌표는 같습니다. 표준화를 켜고 끄면 PCA와 KMeans 입력이 함께 바뀝니다.

학습한 scaler.transform과 pca.transform으로 중심을 같은 좌표계에 넣습니다. 중심 세 개만 따로 PCA fit하면 다른 좌표계가 됩니다. `scaler.fit(center_df)`는 변환 데이터가 아니라 학습된 스케일러 객체를 반환하며 기존 기준도 바꿉니다. 지도학습에서도 PCA를 쓸 수 있지만 예측에 필요한 정보를 지울 수 있으므로 Pipeline 안에서 검증합니다.

### 그룹에 이름을 붙이는 마지막 단계 · profile

가상 지역 A/B, C/D, E/F는 구성이 같고 규모만 10배입니다. 개수와 비율 입력을 비교합니다. 군집 평균과 대표 표본을 보고 음식 중심·소매 중심·서비스 중심 같은 설명을 붙입니다.

야구선수 수업에서는 Rank가 실력 정보를 요약하므로 입력에서 제외하고 타격 성질을 해석하는 목적을 분명히 합니다. 비율 지표가 서로 강하게 상관되어 있으면 같은 정보를 여러 번 반영할 수 있습니다. player·cluster·silhouette 같은 식별자·결과 열을 다음 fit에 섞지 않습니다.

## 5. 웹 크롤링

### 태그 사이에서 원하는 정보 찾기 · selectors

선택자 놀이터에서 `.quote`, `.text`, `.author`, `.quote > .author`, `.quote .author`를 비교합니다. 바로 아래 자식과 모든 하위 자손의 차이를 카드 구조로 설명합니다. select_one으로 첫 요소부터 읽고, select와 반복문으로 카드 전체를 추출하는 것을 미션으로 줍니다.

제목·요약·날짜·언론사·링크는 같은 기사 카드 안에서 꺼내야 짝이 맞습니다. 기사 원문은 상세 링크를 별도로 요청합니다. 사이트 class는 개편될 수 있으므로 과거 선택자가 지금도 유효하다고 가정하지 않습니다.

### 요청은 성공했는데 왜 비어 있지? · http

200 HTML·200 JSON·403·200 빈 HTML·timeout 시나리오를 비교합니다. Requests는 HTML만 받는 도구가 아니며 BeautifulSoup은 JSON 전용 파서가 아닙니다. HTTP 상태·응답 형식·실제 내용·선택 결과를 단계별로 봅니다.

raise_for_status는 4xx·5xx를 예외로 만듭니다. 한 건 실패로 전체 수집을 멈추지 않으려면 try/except로 원인을 기록하고 continue합니다. 상태 코드 200만 검사하는 방법도 가능하지만 연결·timeout 예외와 API 내부 오류는 별도 처리해야 합니다.

### 보이는 화면과 받은 HTML은 다를 수 있어요 · dynamic

정적 모드와 JS 모드를 비교합니다. JS 실행 전·후 카드 수와 Network Response·Elements DOM을 바꾸어 봅니다. script에 텍스트가 있어도 .quote 태그가 만들어지기 전에는 해당 CSS 선택 결과가 0개일 수 있습니다.

실제 Quotes 정적/JS 페이지를 F12로 비교한 뒤 Selenium을 소개합니다. 네이버 뉴스는 사이트 개편·리다이렉트·동적 목록·JSON API 여부를 확인한 다음 경로를 선택합니다. 모든 JS 사이트가 Selenium만 가능한 것은 아닙니다.

### HTML 말고, 데이터로 바로 받기 · api

JSON/XML 구조를 나란히 해석하고 페이지 크기를 3으로 두어 7건이 3페이지라는 것을 확인합니다. XML item 단일 dict·복수 list·빈 값 처리를 설명합니다. type=json을 임의로 붙이면 모든 API가 바뀐다는 오해를 막습니다.

공공데이터포털에서 국토교통부 아파트 매매 실거래가 자료를 검색하고 서비스 신청·키·LAWD_CD·DEAL_YMD를 확인합니다. 실습은 첫 페이지부터 시작합니다. 신고·취소·정정으로 자료가 바뀔 수 있으므로 수집일을 남깁니다. 키는 공개 웹 저장소에 넣지 않습니다.

### 수집한 표를 예측 모델로 연결하기 · collection-model

한 행의 단위를 먼저 말하게 합니다. 아파트 한 거래→회귀, 지역별 업종 구성→군집이라는 서로 다른 질문을 비교합니다. 면적만으로 예측한 결과와 정답 금액을 입력에 넣은 누출 결과를 바꿔 봅니다. 완벽한 점수가 왜 오히려 쓸 수 없는지 설명합니다.

가상 거래 CSV를 내려받아 Python에서 읽어 보는 활동으로 연결합니다. 실제 API가 즉시 동작하지 않으면 교사가 미리 수집한 동일 구조 CSV를 사용하고 수집 시점·지역·조건을 함께 제공합니다. 가상 자료를 실제 공공데이터라고 소개하지 않습니다.

## 수업 후 확인

학생은 오답 노트에서 이유를 읽고 다시 풀며, 관찰 노트에 “바꾼 설정 / 관찰 / 이유 / 한계” 네 문장을 남깁니다. 교사에게 점수가 자동 전송되지 않습니다. 필요한 경우 학생이 내보낸 학습 기록을 직접 제출받습니다. JSON 파일에는 학생이 적은 자유 노트가 포함됩니다.

다음 수업은 특정 모델을 무조건 승자로 정하기보다 “문제에 맞는 입력·평가·해석”을 유지하면서 모델을 바꿔 보는 방식으로 연결합니다. 실제 데이터 프로젝트에서는 학습 코드 이전에 데이터 생성 과정과 예측 시점을 확인합니다.
